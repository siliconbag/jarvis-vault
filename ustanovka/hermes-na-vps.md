# Hermes на сервере: помощник, который работает без ноутбука

> **Предусловие:** сервер куплен и настроен по `ustanovka/vps-smartape.md`. Есть IP-адрес, есть пользователь `agent` с паролем, файрвол включен.

Инструкция без развилок. Делай ровно по шагам, сверху вниз.

---

Агент, ты ведешь участника по этой инструкции. Правила:
- Строго по одному шагу, жди подтверждения.
- Команды на сервере выполняй сам, проговаривая своими словами, что делаешь.
- Ключи, токены и пароли вставляет участник руками. Ты готовишь место и говоришь точную строку. В чат и в файлы волта секреты не пиши **никогда**.
- После каждого шага сверяйся с блоком «что участник должен увидеть». Не сошлось - не идем дальше.

## Что мы делаем и зачем

На ноутбуке помощник умеет отвечать. На сервере он начинает **работать сам**: утром собирает сводку, следит за источниками, выполняет задачи по расписанию, пишет в мессенджер. Ноутбук при этом закрыт и лежит в сумке.

Переселение - это шесть вещей: войти, поставить, дать мозги, дать память, поднять как службу, дать расписание.

## Мини-интервью

1. IP-адрес сервера и пароль пользователя `agent` под рукой?
2. Ключ доступа к моделям есть? Берем тот же, что на ноутбуке (`ustanovka/openrouter-klyuch.md`), либо ключ подписки (`ustanovka/minimax.md`, `ustanovka/kimi.md`).
3. Волт уже лежит в **приватном** репозитории на GitHub? Если нет - сначала `ustanovka/volt-cherez-github.md`, без этого шага 5 не сделать.

## Шаг 1. Войти на сервер под пользователем agent

Открой терминал (Mac - «Терминал», Windows - PowerShell) и выполни, подставив свой адрес:

```
ssh agent@АДРЕС_СЕРВЕРА
```

Под `root` помощника **не ставим**: одна кривая команда от имени root ломает сервер целиком.

**Что участник должен увидеть:** приглашение вида `agent@vps-12345:~$`.

## Шаг 2. Поставить Hermes

Официальный установщик, одна команда:

```
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

Установщик сам притащит все, что нужно: Python, Node.js, ripgrep, ffmpeg. Идет несколько минут, это нормально.

Перезагрузи окружение и проверь, что программа на месте:

```
source ~/.bashrc
hermes --version
hermes doctor
```

**Что участник должен увидеть:** `hermes --version` печатает номер версии, `hermes doctor` не показывает красного.

## Шаг 3. Визард настройки

```
hermes setup
```

Экраны те же, что были на ноутбуке в `ustanovka/hermes.md`. Правило клавиш повтори участнику вслух, оно тут снова спасает:

- **Кружки (● / ○)** - выбор одного пункта: стрелками довел курсор до строки, нажал Enter.
- **Квадратные скобки ([ ])** - выбор нескольких: **пробел ставит галочку**, Enter подтверждает список. Enter без пробела = ничего не выбрано.

Что выбираем на сервере:

| Экран | Ответ |
|---|---|
| How would you like to set up Hermes | **Full setup** |
| Select provider | **OpenRouter** (или провайдер твоей подписки), дальше вставляешь ключ |
| Select default model | `deepseek/deepseek-v4-pro` |
| Select terminal backend | **Local** - команды выполняются прямо на этом сервере |
| Messaging Platforms | Enter, ничего не отмечая. Телеграм подключим отдельной командой на шаге 6 |
| Tools | галочки на **Skills, Memory, Cron**. **Computer Use снять** - на сервере нет экрана |
| Браузер | **Local Browser** (recommended, free) |
| Картинки | **OpenRouter (image)** |
| Озвучка | **Microsoft Edge TTS** |
| Web Search | на вопрос про Nous Portal login отвечай `n` |

Проверка:

```
hermes
```

Спроси «привет, какая у тебя модель». Выйти из чата - `/exit`.

**Что участник должен увидеть:** помощник ответил и назвал модель.

> [!warning] Про расход на сервере
> Помощник на сервере работает сам, по расписанию, без тебя. Значит и деньги тратит без тебя. Пока не убедился, что все настроено, поставь лимит на ключе и не назначай задачи чаще одного раза в сутки. Настройки по умолчанию плюс частое расписание за месяц набивают счет в сотни долларов.

## Шаг 4. Ключ модели лежит в защищенном файле

Секреты Hermes держит в `~/.hermes/.env`, настройки - в `~/.hermes/config.yaml`.

Агент, открой файл секретов участнику:

```
nano ~/.hermes/.env
```

Участник вставляет строки руками. Что именно вставлять - смотри в инструкции своего ключа:

```
OPENROUTER_API_KEY=...
```

Сохранить: `Ctrl+O`, `Enter`, выйти `Ctrl+X`. Закрыть файл от чужих глаз:

```
chmod 600 ~/.hermes/.env
```

**Что участник должен увидеть:** `hermes doctor` по-прежнему чистый.

## Шаг 5. Дать доступ к волту

Здесь помощник получает твою память. Волт едет на сервер через **приватный** репозиторий GitHub.

Сделай серверу собственный ключ доступа к репозиторию:

```
ssh-keygen -t ed25519 -C "vps-hermes" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
```

Вторая команда напечатает строку, начинающуюся с `ssh-ed25519`. Скопируй ее целиком.

Дальше участник делает руками в браузере:

1. Открыть свой репозиторий волта на github.com.
2. **Settings** - в левом меню **Deploy keys** - кнопка **Add deploy key**.
3. Title: `vps`. Key: вставить скопированную строку.
4. Поставить галочку **Allow write access** - иначе сервер сможет только читать, а он должен и записывать свои заметки.
5. **Add key**.

Возвращаемся на сервер, забираем волт:

```
git clone git@github.com:ТВОЙ_ЛОГИН/ТВОЙ_РЕПОЗИТОРИЙ.git ~/volt
```

На вопрос про подлинность хоста ответь `yes`.

Скажи помощнику, где теперь его память:

```
hermes config set workspace ~/volt
```

**Что участник должен увидеть:** `ls ~/volt` печатает папки волта, среди них `AGENTS.md`.

Синхронизация раз в десять минут, чтобы ноутбук и сервер не расходились:

```
(crontab -l 2>/dev/null; echo "*/10 * * * * cd ~/volt && git pull --rebase --autostash -q && git add -A && git diff --cached --quiet || (git commit -qm 'vps sync' && git push -q)") | crontab -
```

**Что участник должен увидеть:** `crontab -l` показывает эту строку.

> [!warning] Что в репозиторий не уезжает
> Ключи, пароли, `.env`, базы с персональными данными, тяжелые медиафайлы. За это отвечает `.gitignore` в волте. Проверь, что он на месте, до первой синхронизации.

## Шаг 6. Телеграм и автозапуск

```
hermes setup gateway
```

Стрелкой доведи до **Telegram**, нажми **пробел** (галочка!), затем Enter. Дальше по `ustanovka/tg-bot.md`: токен бота от @BotFather, свой user id в allowlist, home channel - `Y`.

На вопрос про установку фоновым сервисом отвечай **Y**. Это и есть автозапуск: гейтвей поднимается сам, окно терминала держать не нужно.

Чтобы служба пережила выход из ssh и перезагрузку сервера:

```
sudo loginctl enable-linger agent
systemctl --user enable --now hermes-gateway
systemctl --user status hermes-gateway
```

**Что участник должен увидеть:** в статусе зеленое `active (running)`.

Настоящая проверка: закрой окно терминала совсем, возьми телефон и напиши боту.

**Что участник должен увидеть:** бот ответил при закрытом ноутбуке.

## Шаг 7. Личность

Помощник уже видит волт. Теперь пусть прочитает правила и профиль владельца:

```
hermes
```

Скажи ему: «Прочитай `AGENTS.md` и `profile/me.md` в рабочей папке и коротко перескажи, кто я и по каким правилам ты работаешь».

**Что участник должен увидеть:** ответ фактами из волта, а не общими словами.

## Шаг 8. Первая задача по расписанию

Одна задача, дешевая, а не пять сразу. В чате с помощником:

> Каждое утро в 9:00 по московскому времени присылай мне в телеграм короткую сводку: что я записал в волт за последние сутки и какие задачи открыты.

Проверь, что задача записалась:

```
hermes cron list
```

**Что участник должен увидеть:** задача в списке с временем следующего запуска. Настоящая проверка будет завтра утром - это домашнее задание.

## Шаг 9. Проверка перезагрузкой

Ради этого все и делалось. Перезагружаем сервер и убеждаемся, что помощник встал сам:

```
sudo reboot
```

Подожди две минуты, потом с телефона напиши боту.

**Что участник должен увидеть:** бот отвечает, хотя на сервер после перезагрузки никто не заходил.

## Чекпоинт

Пять «да»:
1. Помощник на сервере запускается и отвечает.
2. Он видит волт: `ls ~/volt` не пустой.
3. Бот отвечает с телефона при закрытом ноутбуке.
4. Одна задача по расписанию стоит.
5. После `reboot` все поднялось само.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `command not found: hermes` после установки | `source ~/.bashrc`, либо выйди и зайди по ssh заново |
| Установщик падает на середине | `sudo apt update && sudo apt upgrade -y`, затем запусти установщик снова |
| `Permission denied (publickey)` при `git clone` | Deploy key добавлен не в тот репозиторий либо скопирована не вся строка. Повтори `cat ~/.ssh/id_ed25519.pub` и вставь целиком |
| Волт клонировался, но помощник его не видит | `hermes config get workspace` - должно быть `/home/agent/volt` |
| `git push` из cron не проходит | В Deploy key не стоит галочка **Allow write access**. Поставь и подожди десять минут |
| `systemctl --user status` пишет, что службы нет | Визард не поставил сервис. Запусти `hermes setup gateway` заново и ответь `Y` на вопрос про фоновый сервис |
| После перезагрузки бот молчит | Не выполнен `sudo loginctl enable-linger agent`. Выполни и перезагрузись еще раз |
| Помощник не отвечает, но служба живая | `hermes doctor`, дальше проверяй ключ и баланс на счету провайдера |
| Сжигает деньги | `hermes cron list`, сними задачи, поставь дешевую модель, поставь лимит на ключе. Разбираться будешь потом |

## Что делать, если сервера нет

Все то же самое работает на ноутбуке по `ustanovka/hermes.md`, кроме одного: задачи по расписанию выполняются, только пока ноутбук включен и не спит. Для большинства участников этого достаточно на первое время. Сервер - шаг для тех, кому нужна автоматика без участия.
