# Как помощник на сервере видит твой волт: схема через GitHub

Это ответ на вопрос, который возникает сразу после переезда на сервер: **волт лежит у меня на ноутбуке в Obsidian, помощник живет на сервере в другой стране. Как он читает мои заметки?**

Через GitHub. Ниже - вся схема и все кнопки.

---

Агент, ты ведешь участника по этой инструкции. Правила:
- Строго по одному шагу, жди подтверждения.
- Все, что на сайте GitHub, участник делает руками. Ты показываешь, куда нажать.
- Токен и ключи участник вставляет сам. В чат и в заметки волта их не пиши.

## Схема одной картинкой

```
   ноутбук                    GitHub                      сервер
   Obsidian  --- push -->  приватный  --- pull -->  Hermes читает
   твой волт <-- pull ---  репозиторий <-- push ---  и пишет сюда же
```

Три копии одного и того же волта. Посередине - приватный репозиторий, он же общая точка правды и он же архив всех версий.

Что это дает на практике:
- Записал мысль в Obsidian на ноутбуке - через десять минут помощник на сервере ее уже знает.
- Помощник ночью собрал сводку и положил заметку - утром она сама появилась у тебя в Obsidian.
- Любую заметку можно откатить к вчерашней версии. Обычное облако так не умеет.

> [!warning] Репозиторий строго приватный
> Там твои заметки о людях, деньгах и клиентах. Публичный репозиторий - это публикация. Проверь галочку **Private** на шаге 2 и не откладывай.

## Шаг 1. Аккаунт GitHub

Если аккаунта еще нет - заведи по `ustanovka/github.md`, там регистрация по шагам, включая ловушку с запросом телефона. Возвращайся сюда с готовым ником.

**Что участник должен увидеть:** github.com открывается, в правом верхнем углу твой ник.

## Шаг 2. Приватный репозиторий под волт

1. На github.com нажми **+** в правом верхнем углу, затем **New repository**.
2. Repository name: `my-vault`.
3. Отметь **Private**. Это обязательно.
4. Ничего не добавляй: ни README, ни `.gitignore`, ни лицензию. Волт приедет со своим.
5. **Create repository**.

**Что участник должен увидеть:** пустой репозиторий и страница с подсказками git.

## Шаг 3. Токен доступа

Пароль от GitHub при отправке файлов не работает - нужен токен.

1. Открой **https://github.com/settings/personal-access-tokens/new**.
2. Token name: `obsidian`.
3. Expiration: 90 дней.
4. Repository access: **Only select repositories**, выбери `my-vault`.
5. Permissions - **Repository permissions** - строка **Contents**: поставь **Read and write**.
6. **Generate token**.
7. Скопируй токен целиком и положи в менеджер паролей. Второй раз его не покажут.

**Что участник должен увидеть:** строка вида `github_pat_...` скопирована и сохранена **вне волта**.

## Шаг 4. Что не уезжает в репозиторий

Сделай это **до** первой отправки: то, что один раз уехало, остается в истории даже после удаления файла.

Агент, проверь, что в корне волта есть файл `.gitignore` и в нем закрыты: ключи и токены (`*.key`, `*.pem`, `.env`), служебные файлы Obsidian, тяжелые вложения, папка `.trash`.

**Что участник должен увидеть:** `git status` не показывает ничего из этого списка.

## Шаг 5. Плагины Obsidian: как они вообще включаются

Синхронизацию делает плагин, а плагины в Obsidian по умолчанию **выключены целиком**. Порядок такой:

1. Открой **Settings** (шестеренка слева внизу).
2. Раздел **Community plugins**.
3. Если видишь надпись про **Restricted mode** и кнопку **Turn on community plugins** - нажми ее. Пока она не нажата, ни один плагин не работает, даже если файлы плагина лежат в волте.
4. Кнопка **Browse**, поиск **по названию, не по идентификатору**.
5. Найди **Obsidian Git**, нажми **Install**, затем **Enable**.

> [!warning] Если плагины не приехали вместе с волтом
> На тренинге часть участников скачала волт раньше, чем в него добавили плагины, у части сработали ограничения рабочего ноутбука. Симптом: папки и заметки на месте, а списки и кнопки не работают.
> Лечение: включить Community plugins как выше и поставить недостающие руками через **Browse**. Ничего страшного не произошло, настройки уже в волте и подхватятся сразу после установки плагина.
> На Windows защита системы может ругаться при первой установке. Это обычное предупреждение о новом файле, а не вирус: разреши установку. На **корпоративном ноутбуке с политиками** установка может быть запрещена совсем - тогда работай на личной машине, спорить с политикой бесполезно.

**Что участник должен увидеть:** в списке Community plugins есть Obsidian Git, переключатель включен.

## Шаг 6. Настроить Obsidian Git

Settings - **Obsidian Git**:

| Настройка | Значение |
|---|---|
| Auto commit-and-sync interval (minutes) | **10** |
| Auto pull on startup | **включить** |
| Commit message | оставить как есть |

Дальше агент связывает волт с репозиторием: инициализирует git в папке волта, привязывает адрес `https://github.com/ТВОЙ_НИК/my-vault.git` и делает первую отправку. При первой отправке система спросит логин и пароль: **логин - твой ник, вместо пароля - токен из шага 3**.

**Что участник должен увидеть:** на github.com в репозитории появились папки волта, и среди них нет ничего из списка исключений.

## Шаг 7. Сервер забирает тот же репозиторий

Это шаг 5 инструкции `ustanovka/hermes-na-vps.md`, здесь коротко ради целостности схемы: на сервере создается собственный ключ, он добавляется в репозиторий как **Deploy key** с галочкой **Allow write access**, репозиторий клонируется в рабочую папку помощника, синхронизация ставится по расписанию раз в десять минут.

Почему у сервера отдельный ключ, а не твой токен: сервер - отдельное лицо. Скомпрометировали сервер - отзываешь один ключ, твой аккаунт цел.

**Что участник должен увидеть:** `ls ~/volt` на сервере показывает те же папки, что в Obsidian.

## Шаг 8. Правило работы в двух местах

**Сначала забери, потом пиши.** Obsidian при запуске тянет изменения сам, помощник на сервере тоже. Но если ты правил заметку на ноутбуке, пока помощник правил ее же на сервере, будет конфликт.

Практика простая:
- Ноутбук просыпается - подожди полминуты, дай Obsidian забрать свежее.
- Конфликт случился - скажи агенту «разреши конфликт в базе». Он покажет обе версии и спросит, какую оставить.

## Шаг 9. Сквозная проверка

Ради этого все и делалось.

1. На ноутбуке создай в Obsidian заметку `_inbox/проверка.md` и напиши в ней любую фразу, например «синхронизация работает».
2. Подожди десять минут.
3. С телефона напиши боту: «прочитай заметку проверка в моей базе и скажи, что там написано».

**Что участник должен увидеть:** помощник цитирует твою фразу. Ноутбук при этом можно закрыть.

Обратная проверка: попроси помощника создать заметку `_inbox/от помощника.md`. Через десять минут она появится у тебя в Obsidian.

## Чекпоинт

Пять «да»:
1. Репозиторий создан и он приватный.
2. Токен выпущен и сохранен в менеджере паролей.
3. Community plugins включены, Obsidian Git стоит и настроен на 10 минут.
4. Волт виден на github.com, секретов там нет.
5. Заметка с ноутбука доехала до помощника, а заметка помощника - до ноутбука.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Просит логин и пароль, пароль не подходит | Пароль GitHub тут не работает. Логин - ник, вместо пароля - токен из шага 3 |
| `Permission denied` или `403` при отправке | В токене не выдано право **Contents: Read and write**, либо репозиторий выбран не тот. Выпусти токен заново |
| Плагин установлен, но ничего не синхронизируется | Не нажат **Turn on community plugins**, либо в волте нет репозитория: попроси агента проверить |
| Заметки уехали, а настройки Obsidian нет | Папка `.obsidian` попала в `.gitignore` целиком. Так быть не должно: игнорируем только `workspace.json` и кэш |
| На сервере файлы старые | Синхронизация на сервере не отработала. Проверь расписание: `crontab -l` |
| Конфликт при синхронизации | Правил в двух местах одновременно. Скажи агенту «разреши конфликт в базе» |
| Случайно отправил ключ или пароль | Удалить файл мало, он остался в истории. Считай секрет скомпрометированным: смени его, потом попроси агента почистить историю |
| Репозиторий оказался публичным | Settings - General - Danger zone - Change visibility - Private. Сделай сразу |

## Если сервера нет

Схема работает и без сервера: ноутбук плюс GitHub - это уже резервная копия с историей версий и синхронизация между твоими машинами. Сервер добавляет к ней только одно, зато главное: помощник продолжает работать, когда ноутбук закрыт.

Альтернативный путь без git - Яндекс Диск, `ustanovka/yandex-disk.md`. Он проще, но истории версий не дает.
