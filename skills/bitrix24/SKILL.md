# Битрикс24: CRM и звонки через агента

Навык даёт агенту доступ к вашему Битриксу на чтение: сделки, стадии воронки, менеджеры, звонки и записи разговоров. Дальше агент сам считает конверсию, находит зависшие сделки, сверяет звонки с карточками и делает разбор.

## Что нужно один раз настроить

### 1. Входящий вебхук
В Битриксе: **Разработчикам → Другое → Входящий вебхук**. Отметьте права **CRM** и **Телефония**, сохраните — получите URL вида `https://ваш-портал.bitrix24.ru/rest/<id>/<токен>/`.

⚠️ **Этот URL — и есть пароль.** Кто им владеет, тот работает с вашим Битриксом от имени создавшего. Не публикуйте его, не отдавайте в чаты и не кладите в файлы базы знаний. Храните в переменной окружения `BITRIX_WEBHOOK_URL` или в системном хранилище паролей, а агенту скажите брать оттуда.

### 2. Права имеют значение
Вебхук видит ровно то, что видит создавший его сотрудник. Хотите смотреть весь отдел продаж — создавайте от администратора или сотрудника с полным доступом к CRM и телефонии. Иначе часть сделок и звонков просто не попадёт в выборку, и вы об этом не узнаете.

### 3. Запись разговоров — обязательное условие
**Чтобы агент мог работать с содержанием звонков, в Битриксе должна быть подключена IP-телефония с включённой записью разговоров.** Без этого API вернёт только факт звонка: кто, кому, когда, сколько длился — но не то, о чём говорили.

Проверьте: **Телефония → Настройки → запись разговоров включена** для нужных сотрудников и линий. Записи хранятся ограниченное время в зависимости от тарифа — если планируете разбирать историю, выгружайте заранее.

Отдельно: встроенная расшифровка в звонках может быть не подключена. Тогда поле с транскриптом придёт пустым, и текст нужно получать самому — скачать аудио и прогнать через распознавание речи (локально или через сервис).

## Как это работает

Агенту нужен тонкий клиент к REST API — обычный скрипт на Python без сторонних библиотек. Попросите агента написать его самому: «сделай мне клиент к Битрикс24 через вебхук, вебхук возьми из переменной окружения, добавь команды: проверка подключения, список сделок по воронке, список пользователей, статистика звонков, скачивание записи».

Дальше всё делается разговором.

### Проверка подключения
Первым делом — убедиться, что вебхук живой и права выданы: агент запрашивает информацию о текущем пользователе и список доступных методов. В ответе должны быть и CRM, и телефония. Нет телефонии — вебхук пересоздать с нужными правами.

### Сделки и воронка
Воронки в Битриксе называются категориями и имеют номер. Сначала попросите агента показать список воронок и найти нужную (например, отдел продаж), потом — список её стадий.

Важный момент: по умолчанию выгружаются **все** сделки за всю историю, включая закрытые. Воронка может на 90% состоять из проигранных сделок, и картина по стадиям исказится. Просите отдельно **только открытые сделки** — это и есть «что в работе сейчас».

Что дальше умеет агент: посчитать сделки и суммы по стадиям, найти зависшие (давно без движения), сравнить менеджеров, посчитать конверсию между стадиями. Идентификаторы менеджеров он сопоставит с именами через список пользователей.

### Звонки и записи
Статистика телефонии отдаёт по строке на звонок: время начала, длительность, кто звонил, номер, входящий или исходящий, к какой сделке привязан, и ссылка на запись, если она есть.

Что из этого собирается:
- **Активность**: сколько звонков у кого, сколько из них результативных. Пропущенные видно по нулевой длительности — это нормально, не считайте их за брак.
- **Сверка с CRM**: был разговор — обновилась ли карточка сделки, поставлена ли следующая задача, сдвинулась ли стадия. Расхождения и есть то, ради чего всё затевается.
- **Содержание**: скачать запись → расшифровать → попросить агента разобрать по вашим критериям (выявил ли потребность, назвал ли цену, договорился ли о следующем шаге).

## С чего начать

1. Создайте вебхук с правами CRM и телефонии, положите в переменную окружения.
2. Проверьте, что запись разговоров включена.
3. Попросите агента написать клиент и проверить подключение.
4. Первый полезный запрос: «покажи открытые сделки отдела продаж по стадиям».
5. Второй: «покажи звонки за вчера с записями и скажи, по каким из них не обновилась карточка».

## Чего не делать

- Не отдавайте вебхук в общие чаты и не сохраняйте его в файлах базы знаний — она может синхронизироваться в облако.
- Не выгружайте записи разговоров и персональные данные клиентов в облачные папки без необходимости: это персональные данные ваших клиентов.
- На демонстрациях и в презентациях показывайте механику, а не реальные суммы, имена менеджеров и телефоны.
