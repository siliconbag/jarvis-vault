# Dashboard-v0: личный дашборд одной командой

Ты собираешь участнику персональный дашборд через v0 (генератор интерфейсов от Vercel). Твои модели текст дашборда не рисуют - рисует v0, ты собираешь данные, промпт и доставку.

## Ключ (прочитай до первого вызова)
- Ключ общий на группу, организаторы публикуют его в чате потока перед слотом дашбордов. Храни его СТРОГО в `~/.hermes/.env` строкой `V0_API_KEY=...` (файл с правами 600). Нет ключа - попроси участника скопировать его из чата потока и сохрани сам.
- НИКОГДА: не записывай ключ в Vault, в git, в чат, в код дашборда, в логи. Vault участника синкается в его GitHub - ключ там равен утечке на всю группу.
- Баланс общий на всех. Один дашборд ~$0.2-0.3. Генерируй только по явной просьбе участника, никаких циклов и авто-повторов. Правки - follow-up в существующий чат (дешевле), не новая генерация.

## Шаг 1. Собери данные
Из подключенных источников участника: туду на сегодня, события календаря на сегодня-завтра, ремайндеры, привычки, важное непрочитанное. Источников еще нет - скажи честно и предложи мок-данные (посмотреть формат) или вернуться после подключения.
Приватность: данные уходят на серверы Vercel (США). Спроси участника, что НЕ включать (та же рамка, что с зарубежным VPS).

## Шаг 2. Промпт
Проси ОДИН самодостаточный файл - это главный паттерн:

```
Create ONE single self-contained index.html file: inline CSS and JS,
no frameworks, no build step, works offline from file://.
Personal day dashboard, dark theme, russian labels:
- блок "фокус дня"
- туду на сегодня (чекбоксы)
- события календаря
- ремайндеры
- трекер привычек (точки за 7 дней)
Данные: <реальные данные участника текстом>
```

Секции подстрой под участника (спроси, что ему важно видеть утром; «важное-несрочное» - сильный блок).

## Шаг 3. Вызов v0
```bash
curl -X POST https://api.v0.dev/v1/chats \
  -H "Authorization: Bearer $V0_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"message": "<промпт>", "modelConfiguration": {"modelId": "v0-pro"}, "responseMode": "sync"}'
```
- Таймаут клиента 180-240 сек: sync висит ~2 минуты, это норма - предупреди участника.
- Модель только `v0-pro` (или `v0-mini` для черновика). Эндпоинт только `/v1/chats` (`/v1/chat/completions` не существует).
- Из ответа сохрани в базу участника: `id` чата (для правок), `latestVersion.demoUrl`, файл `index.html` из `latestVersion.files` (служебный package.json игнорируй). `webUrl` участнику не давай - он не откроется.

## Шаг 4. Отдай результат (двухслойно)
1. `demoUrl` - живое превью. Пометь: из РФ без VPN не открывается; у кого VPN есть - мгновенный просмотр.
2. Надежный путь для всех: сохрани `index.html` и выложи на VPS участника:
```bash
scp index.html user@VPS_IP:~/dashboard/
ssh user@VPS_IP "cd ~/dashboard && nohup python3 -m http.server 8080 >/dev/null 2>&1 &"
```
Дашборд: `http://VPS_IP:8080` - открывается без VPN. Нет VPS - отправь index.html файлом в Telegram, открывается локально в браузере.

## Шаг 5. Правки
«Добавь погоду, перекрась в оранжевый» - follow-up в тот же чат:
```bash
curl -X POST https://api.v0.dev/v1/chats/CHAT_ID/messages \
  -H "Authorization: Bearer $V0_API_KEY" -H "Content-Type: application/json" \
  -d '{"message": "<правка>"}'
```
После правки забери свежие demoUrl/files и перевыложи на VPS.

## Шаг 6. Обновление данных (жизнь после тренинга)
Обновить цифры на дашборде = новая генерация или follow-up с новыми данными. Предложи участнику ритуал: «каждое утро в 8:00 собери данные и обнови дашборд» - но только если он явно попросил регулярность (помни про общий баланс; после тренинга - его личный ключ).

## Проверка ценности
Готовый дашборд отвечает за 10 секунд: «что сегодня важно?». Не отвечает - убери лишние секции follow-up'ом.
