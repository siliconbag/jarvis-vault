# Совет директоров

Один агент даёт один взгляд и склонен соглашаться с тобой. **Совет директоров** — это несколько агентов-экспертов, каждый со своей ролью и своим интересом, которые разбирают твой вопрос **независимо друг от друга**. Ценность именно в изоляции: они не знают ответов друг друга, поэтому расхождения между ними — настоящие, а не подстройка под первое мнение.

Дальше главный агент собирает их ответы: где сошлись (это, скорее всего, правда) и где разошлись (это твои реальные развилки).

## Как это устроено в OpenCode

- Эксперт = **субагент**: отдельный файл с ролью, своим промптом и своей моделью.
- Файлы кладём в папку `.opencode/agent/` внутри проекта (или в `~/.config/opencode/agent/` — тогда доступны везде).
- Вызов: **`@имя-агента` прямо в сообщении** — это работает всегда. Либо просишь главного агента опросить всех по очереди.
- Каждый субагент работает **в своей сессии с чистым контекстом** — то есть реально не видит, что сказали другие.

⚠️ Субагенты запускаются **по очереди**, не одновременно (параллельный режим в OpenCode пока экспериментальный). Для разбора это плюс: видно каждого эксперта отдельно.

## Шаг 1. Собери своих экспертов

Роли должны быть **под твой бизнес**, а не универсальные. Плохо: «эксперт по бизнесу». Хорошо: «директор по франчайзингу, который считает юнит-экономику точки».

Ориентиры по типу дела:

| Твоё дело | Кого звать в совет |
|---|---|
| Производство / товар | Директор по производству, финдир, закупки, продажи |
| Услуги / консалтинг | Директор по продажам, руководитель доставки услуги, финдир, HR |
| Сеть / франшиза | Директор по франчайзингу, операционный директор, маркетинг, финдир |
| Онлайн / продукт | Продукт, рост (growth), техдир, финдир |
| Юридическая практика | Управляющий партнёр, руководитель практики, финдир, развитие клиентов |

Минимум — **3 эксперта**, иначе не будет спора. Больше 6 — дорого и мнения начинают повторяться.

## Шаг 2. Заготовка файла эксперта

Один файл на эксперта: `.opencode/agent/sovet-findir.md`

```markdown
---
description: Финансовый директор в совете директоров — считает деньги и риски.
mode: subagent
---

Ты финансовый директор в моём совете директоров.

Твоя оптика: деньги. Юнит-экономика, окупаемость, кассовый разрыв, стоимость
привлечения, что будет при худшем сценарии. Ты не оптимист и не пессимист —
ты считаешь.

Контекст обо мне и компании: читай папку `viki/` (профиль, компания, цели).
Если данных для расчёта не хватает — прямо скажи, каких цифр не хватает,
и посчитай при нескольких допущениях.

Отвечай так:
1. Как ты видишь ситуацию с точки зрения финансов (3-5 пунктов)
2. Главный риск, который другие недооценят
3. Твоя рекомендация — конкретное действие, а не «надо проанализировать»
4. При каких условиях ты изменишь мнение

Не подстраивайся под то, что мне приятно услышать. Если идея плохая —
скажи прямо и объясни цифрами.
```

Остальных делаешь по тому же скелету, меняя **оптику** и **что он видит**. Ключевое в каждом файле: своя оптика, доступ к `viki/`, требование конкретной рекомендации и запрет подстраиваться.

## Шаг 3. Сформулируй вопрос

Совет бесполезен на вопросе «как дела в бизнесе». Он полезен на **развилке**.

Плохо: «как мне расти?»
Хорошо: «У меня есть 2 млн свободных. Вложить в открытие второй точки или в маркетинг существующей? Точка окупается за 14 месяцев, маркетинг даёт +30% выручки на 3 месяца».

Формула: **ситуация + цифры + варианты + что для тебя важно**.

## Шаг 4. Запусти совет

Главному агенту:

```
Собери совет директоров по моему вопросу: <вопрос>.
Опроси по очереди @sovet-findir, @sovet-operacii, @sovet-marketing.
Каждому передай мой вопрос и скажи читать viki/ для контекста.
Их ответы не показывай друг другу.
Потом сведи: где все согласны, где разошлись, и какие развилки остались за мной.
```

Либо вручную: `@sovet-findir разбери мой вопрос: ...` — и так каждого.

## Шаг 5. Синтез — самое ценное

Попроси главного агента свести результат так:
- **Консенсус** — с чем согласны все. Это можно делать не раздумывая.
- **Расхождения** — где эксперты спорят, и почему. Здесь твоё решение, его нельзя делегировать.
- **Что упустили все** — отдельный вопрос агенту: «чего не увидел ни один эксперт?»
- **Чего не хватает для решения** — какие данные нужно добрать.

Сохрани разбор в базу (`viki/`) со ссылкой на дату — через месяц сравнишь с тем, что вышло на самом деле.

## Про расход

Совет — самая дорогая команда: каждый эксперт читает контекст заново. На выданном ключе гоняй **волнами по 2–3 эксперта**, а не всех сразу, и не давай им читать весь Vault целиком — только нужные страницы. Для тяжёлых разборов ставь экспертам сильную модель, для быстрых — дешёвую (модель указывается в файле эксперта).

## Когда это не нужно
Если ответ ты уже знаешь и хочешь подтверждения — не зови совет, он честно испортит настроение. Совет нужен там, где ты действительно не решил.
